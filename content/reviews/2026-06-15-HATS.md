## 一句话总结

HATS 用“人类 pilot + MLLM copilot”的方式解决四臂遥操作的数据采集难题：人类直接控制两条主臂，智能体控制两条辅助臂，操作者通过语音进行监督和纠错。

![HATS 概览](/reviews/2026-06-15-HATS/fig1-overview.png)

*图 1. HATS 允许单个操作者在 MLLM 智能体辅助下采集四臂操作数据。*

## 研究问题

很多真实操作任务超过了双臂系统能力，例如搬抬桌子、铺布、在大工作空间中并行抓取多个物体。多臂系统可以提升效率，但示教采集很困难。单人控制多臂会带来巨大认知负担，需要频繁 mode switching；多人控制能分担负担，但需要高沟通成本，动作同步也容易不一致。

HATS 试图在二者之间找到平衡：**只用一个人，但给他一个能理解任务并控制辅助臂的 MLLM copilot。**

## 方法概述

![系统总览](/reviews/2026-06-15-HATS/fig2-system-overview.png)

*图 2. HATS 包含视觉感知、LLM 任务规划、人-智能体协作和语音监督四个模块。*

系统将四条机械臂分为两类：

- **Primary arms**：由人类操作者直接遥操作，执行关键物体交互；
- **Assistive arms**：由训练-free MLLM-based agent 控制，执行抓取、放置、支撑、抬升等辅助子任务。

HATS 的 pipeline 包括四个模块：

1. **视觉感知**：用 AnyGrasp 和 VLM 从 RGB-D 输入中提取抓取姿态和目标位置；
2. **任务规划**：LLM planner 根据任务描述生成辅助臂的可执行动作序列；
3. **协作执行**：智能体控制辅助臂，人与智能体并行执行；
4. **人在回路监督**：操作者用语音命令触发 retry、stop、go home 等高优先级纠错。

这个分工的价值在于：人类保留对关键操作的直觉控制，智能体承担结构化、可规划的辅助自由度。

## 实验与结果

![任务套件](/reviews/2026-06-15-HATS/fig3-task-suite.png)

*图 3. HATS 评估七个真实多臂任务，包括清桌、装箱、开抽屉、清洗、倒物、铺布和抬桌。*

作者设计了七个真实任务，并按耦合程度分为独立执行、弱耦合协作和强耦合协作。系统与三类基线比较：Solo-Switching、Full-Agent 和 Dual-Human。

![系统结果](/reviews/2026-06-15-HATS/fig4-system-results.png)

*图 4. HATS 在系统评估和下游策略训练中均接近或优于强基线。*

主要结果包括：

- HATS 平均成功率达到 **86.4%**，接近 Dual-Human 的 90.0%；
- 在强耦合任务中，HATS 能缓解单人 mode-switching 的并发瓶颈；
- 使用 HATS 数据训练的下游 imitation policy，与使用 Dual-Human 数据训练的策略表现相当；
- HATS 在用户研究中显著降低 NASA-TLX 负担。

![工作负担](/reviews/2026-06-15-HATS/fig5-workload.png)

*图 5. NASA-TLX 主观负担结果显示，HATS 降低了体力与时间压力。*

## 硬件与规划细节

![硬件系统](/reviews/2026-06-15-HATS/fig6-hardware-setup.png)

*图 6. 硬件系统包括四条 Agilex Piper 机械臂、RealSense 相机和 GELLO 风格 leader 控制接口。*

![规划 prompt](/reviews/2026-06-15-HATS/fig7-planner-prompt.png)

*图 7. LLM planner 使用结构化系统 prompt，约束空间分配、碰撞避免和 JSON 输出格式。*

作者的 agent 并不是端到端低层控制模型，而是通过结构化 prompt 生成 motion primitive 序列，再由调度和执行模块落到机械臂动作。这种设计牺牲了一些开放性，但换来了稳定、可控和可调试。

## 优点

- **问题设置现实**：多臂示教采集确实受单人负担和多人协调成本制约；
- **人机分工清楚**：人负责关键操作，agent 负责辅助动作；
- **系统评估完整**：同时评估成功率、完成时间、下游策略质量和用户负担；
- **语音监督实用**：提供低成本高优先级安全/纠错通道；
- **对数据采集很有价值**。

## 局限

- Agent 依赖预定义 motion primitives，不是真正开放动作生成；
- 当前任务经过结构化设计，动态、拥挤或非预期场景下适应性有限；
- 语音监督要求操作者持续关注辅助臂，仍有认知负担；
- 四臂系统硬件复杂，复现实验成本较高；
- LLM planner 的可靠性依赖 prompt、验证器和任务结构。

## 讨论问题

1. 多臂遥操作中，人类和智能体的控制边界应如何动态调整？
2. 语音监督是否足以处理快速接触失败，还是需要触觉或视觉异常检测？
3. HATS 采集的数据是否会带有 agent planner 的偏差？
4. 能否让 agent 从人类纠错中在线学习，而不是始终 training-free？
5. 如果扩展到更多机械臂，pilot-copilot 范式是否仍然可扩展？

## 与本实验室研究的关系

HATS 与遥操作示教采集和共享自治高度相关。它给出的关键启发是：示教系统不一定要在“全人工”和“全自动”之间二选一，而可以把人类控制和基础模型规划结合成分工明确的数据采集流程。这对未来双臂、四臂或多机器人协作数据采集都有参考价值。

## 可能的后续方向

- 将 HATS 式 copilot 引入双臂或灵巧手遥操作平台；
- 用视觉/触觉异常检测自动触发语音外的安全干预；
- 研究 agent 控制辅助臂时产生的数据偏差；
- 让 copilot 从人类纠错中逐步学习 task-specific coordination；
- 结合 VLA 或世界模型替换固定 motion primitives。
